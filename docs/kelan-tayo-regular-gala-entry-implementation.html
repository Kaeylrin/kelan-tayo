IMPLEMENTATION GUIDE

Kelan Tayo — Regular Gala Entry Screen

v1.2.0 · frontend build guide for /gala

Scope lock: this document covers only the visual redesign and frontend structure of the /gala entry screen. It complements, and does not replace, the existing "Kelan Tayo — Regular Gala" implementation guide, which covers the database schema, magic link auth flow, and backend logic. Use both together: this one for what the page looks like and how it's built, the other for how the data and sign-in actually work.

1. Why the Previous Version Needed a Redesign

The original build had the right content (headline, feature list, sign-in form, three-step explanation) but no visual hierarchy. Feature callouts read as plain buttons rather than highlights, the sign-in card floated with no distinct framing, and nothing matched the polish already established on the landing page and the base app screens. The redesign keeps every existing content decision, it changes presentation only.

2. Design System, Reused

No new design tokens are introduced. This screen reuses the exact same CSS variables, fonts, and component patterns already established across the landing page and the base app (kelantayo blue, gold accent, Baloo 2 display type, Plus Jakarta Sans body text, the same card, chip, and button shapes).

  • Nav bar: same component as the landing page, including the scroll-to-pill behavior already implemented there
  • Card style: same rounded corners, border, and background as existing cards (create-plan card, stat cards)
  • Buttons: same gold primary button with the drop-shadow lip, same hover and press treatment

4. Component Details

Nav badge

A small pill labeled "Regular Gala" sits beside the logo, distinguishing this screen from the base app without needing a separate header treatment. Uses the same faint border and rounded shape as other small badges on the site.

Feature chips

Each of the three chips (Recurring schedules, Group overlap view, One-click exceptions) pairs a small line-icon with a label, inside a pill-shaped card. This replaces the original plain-button treatment, chips read as highlights, not actions, so they don't compete visually with the actual Save your spot CTA below them.

Save your spot card

Restyled to match the create-plan card's structure directly: a label above the input, a full-width input field, a full-width primary button with the same drop-shadow treatment used elsewhere, and a small reassurance line beneath it. This card is the single clear action on the page, everything else is either context or explanation.

How it works, step cards

Presented as three cards side by side (stacking to one column on mobile) rather than the landing page's alternating image-and-text layout, since this screen has no app screenshots of its own yet to alternate against. Each card uses the same numbered gold badge already established as a pattern on the landing page's step section.

Reassurance strip

A single dashed-border card with one short paragraph, explicitly stating that the base app remains unchanged and login-free. This directly addresses the tone concern raised earlier in planning, that Regular Gala should never make the rest of Kelan Tayo feel like it quietly became a different product.

5. What This Screen Does Not Yet Include

  • The actual post-sign-in experience (/gala/dashboard, /gala/:galaId), this document covers the entry screen only
  • Real screenshots of the recurring schedule grid or overlap view, placeholder text-only chips are used until those screens exist
  • Any wiring of the email input to Supabase Auth, that belongs to the backend implementation guide, this document is presentation only

6. Definition of Done

  • The /gala entry screen visually matches the established Kelan Tayo design system, no new colors, fonts, or component shapes introduced
  • The three feature chips are visually distinct from the Save your spot button, so there's no ambiguity about which element is the actual call to action
  • The Save your spot card is clearly the focal point of the page, both compositionally and through the reassurance card giving it space to stand alone
  • The reassurance strip is present and clearly states the base app stays unaffected
  • Footer displays v1.2.0
  • Page is responsive, chips wrap gracefully and step cards stack to one column on small viewports
